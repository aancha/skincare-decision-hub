01 / Product & ownership

From a shopper’s question
to a working product.

Skincare shoppers compare fragmented catalogs, ingredient details, prices, and routine compatibility. I built a connected workflow that helps them discover options, compare evidence, and assemble a shortlist and routine.

I owned the product flow and application architecture: the HTML/CSS/JavaScript client, Python/SQLite services, catalog ingestion and normalization, LLM explanations, MCP tools, validation, and release decisions.

I used coding assistants and existing libraries during implementation, while retaining responsibility for design choices, integration, and verification.

Tool interface: Model Context Protocol (MCP) exposes product capabilities through tool discovery and invocation. A tool call does not inherently call an LLM.

03 / Engineering decisions

Design for the failure path.

A

Keep explanations optional.

Resolve selected product IDs, build bounded context, and apply deterministic guardrails before provider execution. Recognized guarded questions retain every matched caution and select no product and skip provider execution. Timeouts, refusals, and invalid output return a fact-based deterministic explanation.

Concrete check: an unknown product citation is rejected and follows the fallback path in the standalone example.

Tradeoff: fallback text can be less useful than a good model answer. That comparison needs separate evaluation.

Read the explanation implementation →
B

Keep ranking authority explicit.

Deterministic logic controls eligibility and ranking. Response validation checks exact fields and whether cited IDs belong to the selected products. MCP dispatch limits operations and returned fields.

Concrete check: a regression test demonstrates that a valid citation ID can still accompany unsupported prose.

Boundary: schema and citation membership checks do not establish factual support. A learned-ranker experiment failed promotion criteria, so deterministic ranking retained authority.

05 / What comes next

Measure usefulness
with fresh evidence.

My next step is to compare actual model answers with deterministic output using fresh cases and blinded human review. I would measure usefulness, unsupported claims, latency, and token usage, and observe unfamiliar users completing the product journey.

The product supports skincare decisions; it does not establish individual effectiveness or medical certainty.
